# Garden of Zo platform

- Canonical project ownership labels and role legend: `docs/project-labels.md`. Use `skills/garden-project-labels/SKILL.md` when classifying projects, reviewing labels or maintaining ownership metadata; workspace `Skills/garden-project-labels` links to this repository's skill. Keep category/sub-category separate from catalogue display categories and access levels. Consult pending ownership entries before applying labels; recording the legend does not move folders or change services.
- This is the `GOZ | PLATFORM` app: Garden homepage, Atlas, catalogue and read-only private inventory. Repository remote: `sayyidkhan/garden-of-zo`. Router infrastructure is the sibling `../zo-router` checkout with its own repository and services.
- Managed process service `zo-platform` serves public Garden on loopback 8834 and private Garden on loopback 8835. Listener configuration determines access; never trust a request header, Host or query parameter to grant private access. Never expose these listeners directly.
- Existing public/private gateway roots `/`, `/#atlas`, `/#list`, Garden assets and private `/operations/*` are forwarded by zo-router. Existing app routes and transports bypass this app. `/health` on either gateway reports router health; platform health is checked directly on its loopback listeners.
- Change visuals in `view.ts`, `client/`, `assets/`, and `operations/view.ts`/`list.css`. Change app descriptions, authors, artwork, graph positions and catalogue visibility in local `catalogue.json`/`authors.json`. Routing manifests belong to `../zo-router`; read through `ROUTES_DIR`, never import router runtime code or write manifests from this app.
- Preserve explicit Orin profile links, Runa's host default, private-link authentication, Atlas camera/connection animation, list state and legacy `/operations` redirects. Public Garden must never return inventory data or load its private client.
- Both landing pages share the public Garden design, introduction and “Open sky atlas” label. Keep private inventory and access-specific destination links behind the existing authentication boundary.
- Public/private List entries and Atlas details display ownership from `project-labels.ts`, maintained against the canonical legend. New catalogue routes require an explicit mapping. Preserve proposed status for unresolved ownership; private inventory identifiers without a mapping show “Ownership pending”. Never send the full ownership registry or operational records to the public client.
- Inventory remains read-only. Keep process state, HTTP reachability, declared state and verified health distinct. Exclude secrets, raw environment/commands, conversations and database records. Preserve observation times on stale data. Local backup evidence does not establish off-host protection or tested restoration.
- Automation metadata is a private, gitignored `operations/automations.local.json` snapshot. Page refresh does not update that source. Do not commit it, live databases, secrets, or backups.
- Run `bun test` for changes. For browser checks run `python3.12 tests/unified-list.browser.py` and `bun tests/atlas-camera.browser.ts`; use existing gateway URLs in test environment variables when checking deployment. Keep all scratch files and screenshots under `_scratch/` and suffix copied tests `.bak`.
- Restart only `zo-platform` for interface/inventory/catalogue changes. Gateway restarts are needed only for routing/transport code or routing configuration changes. See `docs/migration.md` for cutover and rollback details.
