# Garden of Zo platform

The GOZ platform app: Garden homepage, Atlas, catalogue and read-only private inventory. Repository: `sayyidkhan/garden-of-zo`; folder: `Start/garden-of-zo/zo-platform`. Routing and connection infrastructure live in sibling `../zo-router` and repository `sayyidkhan/zo-router`.

## Run and maintain

Managed process service `zo-platform` (`svc_YIhvL4JC_vw`) runs `bun server.ts` with `ROUTES_DIR=/home/workspace/Start/garden-of-zo/zo-router`. One app serves two fixed loopback listeners: 8834 for public Garden, 8835 for private Garden. Configure ports with `PLATFORM_PUBLIC_PORT` and `PLATFORM_PRIVATE_PORT`. Do not register an external endpoint for these ports. Gateway visibility and Zo sign-in remain the access boundary.

Install graphics dependencies with `bun install --frozen-lockfile`. Run `bun test` after changes. Restart only `zo-platform` for UI, inventory, authors or catalogue metadata changes. No gateway restart is required for these changes. See `docs/migration.md` for deployment, protected behaviour, recovery and verification.

Both existing gateway roots continue to serve `/`, `/#atlas` and `/#list`. Existing app paths bypass this process. Public Garden never serves operational inventory or its client; public/private mode is fixed by listener configuration, never selected using client headers or Host.

## Private inventory

`operations/view.ts` and `list.css` render the unified private List. Preserve search, tabs, filters, numeric size sorting, selected entity/dependencies and URL state. Legacy `/operations[/]#entity=...` redirects into `/#list` while retaining selection. Public `/operations/*` must return 404.

Inventory reads supervisor state, route manifests, PAL registry/workflows and scoped SQLite/DuckDB file metadata. It excludes secrets, raw environment/commands, conversations and database rows. Host Codex databases are host runtime. The documented YouTube last-success aggregate is the only workflow-store query. Preserve scan bounds, error reporting, stale observation times and last-good cache handling. Process state, HTTP response, declared configuration and verified application health are different facts.

`operations/automations.local.json` is a private gitignored Zo schedule snapshot; page refresh does not refresh this source. **Update task list**, available in the stale-list finding and Inventory info, calls the private POST endpoint `/operations/api/scheduled-tasks/sync`. The server uses its existing `ZO_CLIENT_IDENTITY_TOKEN` to call only `list_automations` through Zo’s MCP endpoint; credentials and task instructions never reach the browser or saved snapshot. It validates the complete response before atomically saving task IDs, names, schedules and enabled states with the actual observation time. Concurrent requests share one fetch, repeat calls are limited to once per 30 seconds, and failures preserve the previous list. Cross-site requests and requests without the action header are rejected; the public listener returns 404. **Open Zo Scheduled Tasks** opens the task settings for inspection. Updating Garden’s copy does not change tasks, run them or retrieve run results. The finding distinguishes saved-list age from task execution and shows the last copy time. Local Runa backup evidence is not proof of off-host protection or a tested restore. Inventory does not restart services, run workflows or change permissions.

Run `python3 operations/database_backups.py --inventory <private-fresh-inventory.json>` to cover SQLite application and agent-runtime files in a complete fresh private inventory. By default it reuses checksum-verified existing backups and creates a snapshot only when none is known. Orin and Runa native database backups are recognised through their source-specific locations and matching checksum manifests; they remain owned by their app's backup procedure. Unverified existing copies require review instead of an extra snapshot. Obtain inventory JSON from the private loopback endpoint with `?fresh=1`; keep the input under `_scratch/`. Package-store indexes are development caches, not application data. This operator command is separate from read-only inventory discovery; it does not run automatically.

Use `--dry-run` to inspect decisions without writing backups or evidence. Reusing a snapshot preserves its original time, so old-backup warnings remain meaningful. Use the owning app's backup procedure to refresh app-managed copies. Recognised app-owned sources never fall back to Garden snapshots, even with missing or invalid native evidence or `--refresh-existing`. Discovery checks current native manifests on every observation. Orin Projects keeps one rolling copy under `/root/.hermes/backups/orin/current-projects/`; update it with Orin's `scripts/backup.py --projects-only`. Karma is exclusively managed by Orin: one rolling copy under `/root/.hermes/backups/orin/current-karma/`, maintained daily at 03:00 Asia/Singapore. Discovery rechecks its current checksum manifest so replacements do not depend on a saved Garden checksum. Garden never creates a Karma snapshot, even if native evidence is missing or invalid; use Orin's `scripts/backup.py --karma-only` and inspect its job output. Orin checks the live schema, integrity and foreign keys, verifies the candidate and an isolated restore before atomic replacement, and keeps the existing snapshot time when content is unchanged. For an explicitly requested fresh Garden snapshot, pass `--refresh-existing`; verified app-managed copies are still reused. Runs are serialised with a private file lock. Existing snapshots are never pruned or overwritten by this command.

Snapshots use SQLite online backup, include committed WAL data, and undergo integrity checks plus an isolated restore with matching table counts. Source databases are never replaced. Each snapshot and its parent directory use private permissions. Copies live under private `/home/workspace/Data/database-backups/<UTC timestamp>/`, except Stakefolio database copies, which remain inside its ignored `stakefolio-ledger/backups/garden-databases/`. These are database-only copies: they do not replace Stakefolio's complete database/media/configuration recovery procedure or agent credential backups.

The gitignored `operations/backups.local.json` records source-to-snapshot paths, checksums, snapshot times and verification method, without rows. Discovery checks that each snapshot remains in approved private storage and matches its checksum before recognising it. Native evidence is restricted to that app's backup root and source filename; matching an app checksum does not claim Garden tested a restore. Missing or changed copies remain unconfirmed; copies older than 24 hours produce a separate freshness warning. Existing Runa manifest evidence remains available with its more limited verification description. No pruning, automatic schedule or off-host upload is configured. Backups must stay outside Git and public routes.
